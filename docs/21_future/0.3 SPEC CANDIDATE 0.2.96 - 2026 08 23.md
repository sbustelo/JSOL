# SPEC CANDIDATE 0.3 \* draft 23 AUG 2026

## 1\. TYPES, PREFIXES, AND LEXICAL RESTRICTIONS

Variable typing is defined statically by the first character (or characters) after the `$` sigil.

-   **Core (1 letter):** `$i` (Index), `$q` (Quantity), `$n` (Number/Float), `$s` (String), `$a` (Array), `$m` (Map), `$b` (Boolean), `$f` (Function), `$x` (Regex), `$y` (Byte/Binary).
-   **Custom (3+ letters):** Allows specific domains (e.g., `$colHex`). The linter will validate that they do not collide with core long names or target keywords.
-   **User Restrictions:** Declaring variables that start or end with underscore (`_`) is prohibited. The `$JSOL_` prefix is reserved for the compiler. Prefixes that conflict with any of the target languages are prohibited.

## 2\. ORTHOGONALITY OF SEQUENCES AND MUTATION

Strings (`Str`) and arrays (`Arr`) share semantically equivalent operations.

-   **Length:** Standardized as `Str.len($s)` and `Arr.len($a)`. Same logic, different domain.
-   **Concatenation:**
    
    -   `Arr.concat($a1, $a2)`: Concatenates two arrays, generating a new one.
    -   `Arr.concat($a, $x)`: If the second argument is a scalar, it is automatically wrapped and appended to the end (e.g., `Arr.concat([1,2,3], "ETC")` results in `[1,2,3,"ETC"]`).
-   **Convenience Mutation (Stack):** The primitives `Arr.pop($a)` and `Arr.shift($a)` operate as in-place exceptions. They **mutate** the original array and **return** the extracted element.

## 3\. REGULAR EXPRESSIONS (REGEX)

JSOL compiles to the native engines of target languages using a safe subset that guarantees linear time (excluding lookarounds and complex backreferences).

-   **Replacement Syntax:** The literal dollar sign (`$1`, `$2`) is used to reference captured groups in `Regex.replace`. The compiler translates this token to the corresponding native syntax (`\1` in Python, unchanged in JS/PHP).

## 4\. MATHEMATICS AND STRICT COERCION (EXCEL CRITERION)

Any divergence between base languages requires a design decision.  
One possible policy for "breaking ties" is to resolve in favor of Excel's expected behavior (as Excel is the environment where business logic  _actually_ lives).

-   **Core Math:** Primitives are consolidated with the suffix `X` to indicate Excel-style resolution: `Math.modX`, `Math.roundX`, `Math.logX`. Native `Math.ln` is included.
-   **Strict Casts:** `Cast.toInt` and `Cast.toFloat` do not tolerate garbage (e.g., `"12abc"` fails, does not truncate). In case of failure, resolution is delegated to the Shadow Channel.

## 5\. SHADOW CHANNEL (FALLIBLE ERROR HANDLING)

Absolute elimination of "magic numbers" (`-1`, `NaN`) in the data channel. Errors travel through an invisible parallel channel.

-   **Base Mechanism:** Every function marked as `"fallible": true` returns a valid type value in its main variable and injects error metadata into the 'shadow'.
-   **`JSOL.ok()` (Anonymous Shadow):** Evaluates the last executed fallible function. It is forcibly reset at the start of each statement. If multiple fallible calls are nested within the same statement, the first failure **blocks** the shadow state to `false` to preserve the root cause.
-   **`JSOL.ok($var)` (Named Shadow):** Syntactic sugar available for direct assignments. The compiler will generate `$mJSOL_varName_ok` variables.
-   **Development Interpreter:** One design hypothesis is that the development tool runs an interpreter with polyfills instead of continuous compilation. For an interpreter to support `JSOL.ok($var)`, a "Pre-Massage" _source-to-source_ process (without using `EVAL`) would need to be implemented to inject shadow names, reset states, and allow polyfills to update the channel correctly. This considerably complicates the idea, leaving aside that in the development interpreter, mechanisms like `console.log` will be available, making `JSOL.ok($var)` less indispensable. But all of this makes the idea of an interpreter lose its appeal.

## 6\. COMPILER ARCHITECTURE AND TRANSPARENCY

Structural refactoring applying the Open/Closed Principle (OCP) to scale targets without touching the core engine.

-   **Dynamic Backend Registration:** The monolithic pipeline is replaced by a function map (e.g., `$mBackendRegistry["python"] = $fCompileToPython`). Each target manages its own internal passes.
-   **Auto-`use` in PHP:** The compiler automatically injects free variables captured by closures (`use (&$var)`), deprecating `JSOL.use` in business code.
-   **Sanitization in Python (Level 2):** The `$` sigil is removed **without replacement**. If the resulting variable collides with a Python or JSOL keyword (e.g., `pass`, `str`), the compiler injects an underscore **exclusively at the end** of the word (`pass_`), complying with PEP 8 and avoiding name-mangling.

### 1\. `Str.*` (Text Manipulation)

Operates strictly on Unicode code points to ensure cross-platform integrity.

-   `Str.len($s)`: Code point count.
-   `Str.sub($s, $start, $len)`: Substring by code point, avoiding surrogate splitting.
-   `Str.char($s, $idx)`: Extracts code point at specific index.
-   `Str.fromChar($code)`: Constructs string from Unicode code point.
-   `Str.indexOf($s, $needle)`: Search. **Fallible** (`JSOL.ok` channel).
-   `Str.contains($s, $needle)`: Infallible boolean membership.
-   `Str.startsWith($s, $needle)` / `Str.endsWith($s, $needle)`: Prefix/suffix evaluation.
-   `Str.split($s, $d)`: Partition to array. If `$d` is empty, splits by code point.
-   `Str.replaceAll($s, $r, $rep)` / `Str.replaceFirst($s, $r, $rep)`: Exact string replacement.
-   `Str.same($sA, $sB, $mStrOptions?)`: Flexible equality with `ignoreCase` and `ignoreDiacritics` options.
-   `Str.padStart($s, $len, $sPad)` / `Str.padEnd($s, $len, $sPad)`: Alignment and padding.
-   `Str.repeat($s, $q)`: N-times repetition.
-   `Str.concat($a, $b, ...)`: Variadic. Mandatory form for mixed concatenation, applies `Cast.toStr` before joining.

### 2\. `Arr.*` (Sequential Arrays)

Isomorphic semantics based on pass-by-value (immutability by default) with documented stack exceptions.

-   `Arr.len($a)`: Total element count.
-   `Arr.push($a, $item)`: Appends element to the end.
-   `Arr.pop($a)`: **Mutates in-place** and returns the last element. **Fallible**.
-   `Arr.shift($a)`: **Mutates in-place** and returns the first element. **Fallible**.
-   `Arr.unshift($a, $item)`: Inserts element at the beginning.
-   `Arr.slice($a, $start, $end)`: Range copy with `(start, end)` semantics.
-   `Arr.indexOf($a, $item)`: Strict search. **Fallible** (`JSOL.ok` channel).
-   `Arr.contains($a, $item)`: Boolean membership.
-   `Arr.join($a, $d)`: Joins to string, parsing `null` to `""` via `Cast.toStr`.
-   `Arr.concat($a1, $a2, ...)`: Merges without mutating. If it detects a scalar, it automatically wraps it as the last element.
-   `Arr.sort($a, $criterion)`: Sorting. Requires an explicit comparator.
-   `Arr.map($a, $f)`, `Arr.filter($a, $f)`, `Arr.reduce($a, $f)`: Iterators. Support single-expression lambdas or named functions.

### 3\. `Map.*` (Hash Dictionaries)

Two-dimensional tables with immutable keys and guaranteed insertion order.

-   `Map.create(...)`: Initialization. For duplicates, assumes _last-wins_.
-   `Map.has($m, $key)`: Infallible existence check (evaluates key, not value).
-   `Map.get($m, $key)`: Value retrieval. **Fallible** if key does not exist.
-   `Map.keys($m)` / `Map.values($m)`: Returns uniaxial lists.
-   `Map.count($m)`: Number of pairs.
-   `Map.merge($m1, $m2, ...)`: Union of maps returning a new instance.

### 4\. `Math.*` (Arithmetic Unit - Excel Criterion)

Asymmetric resolutions always prioritize classic office convention.

-   `Math.floor($n)` / `Math.ceil($n)`: Directional rounding.
-   `Math.roundX($n)`: Strict "half away from zero" rounding.
-   `Math.trunc($n)`: Decimal truncation, implicitly used for `$q`.
-   `Math.abs($n)` / `Math.pow($b, $e)`: Magnitude and exponentiation.
-   `Math.sqrt($n)` / `Math.cbrt($n)`: Real Euclidean roots.
-   `Math.modX($a, $b)`: Modulo inheriting divisor sign.
-   `Math.min($a, $b)` / `Math.max($a, $b)`: Extrema. **Fallible** with `NaN` inputs.
-   `Math.ln($n)`: Natural hardware-base logarithm.
-   `Math.logX($number, $base=10)`: Configurable logarithm compiled to target's optimal method.
-   `Math.sin($n)`, `Math.cos($n)`, `Math.tan($n)`, `Math.asin($n)`, `Math.acos($n)`, `Math.atan($n)`, `Math.atan2($y, $x)`: Trigonometric set.
-   `Math.E`, `Math.PI`: Universal constants.

### 5\. `Bit.*` (Unsigned Binary Logic)

Operations constrained by default to unsigned 32-bit magnitude.

-   `Bit.and($a, $b)`, `Bit.or($a, $b)`, `Bit.xor($a, $b)`, `Bit.not($a)`: Logic gates.
-   `Bit.shiftL($a, $n)`, `Bit.shiftR($a, $n)`: Unambiguous logical shifts.

### 6\. `Cast.*` (Strong Conversion)

Strict discipline for cross-domain conversion.

-   `Cast.toInt($val)` / `Cast.toFloat($val)`: **Fallible**. Reject hybrid strings, do not parse partially.
-   `Cast.toStr($val)`: Safe mapping to text (e.g., `null` -> `""`).
-   `Cast.toBool($val)`: Normalized falsity determinism (Truthiness).
-   `Cast.toIntBase($s, $base)` / `Cast.toStrBase($num, $base)`: Cross-platform radix transformations for IPAX.

### 7\. `Regex.*` (Safe Expressions)

Guaranteed linear execution in host engines (RE2 / Rust compatible).

-   `Regex.match($s, $r)`: Extraction.
-   `Regex.replace($s, $r, $rep)`: Substitution using strict native syntax `$N` for capture interpolation.
-   `Regex.test($s, $r)`: Fast boolean validation.

### 8\. `JSOL.*` (Internal Control and Metadata)

Ecosystem management and failure heuristics.

-   `JSOL.ok()` / `JSOL.ok($var)`: Side channel for validating functions with `"fallible": true`. Silently resolves shadow variables.
-   `JSOL.range($qFrom, $qTo, $qStep, $qMaxTimes)`: Iteration sugar for for-loops that automatically injects tabular metadata (`$JSOL_i`).
-   **Deprecated:** `JSOL.use()` (automated by the engine).

## ISOMORPHISM-AUDIT.md

JSOL strives to guarantee **Deterministic Parity**: the same `.jsol` source compiled to any target language must produce bit-for-bit identical output. Semantic divergences between languages — where the same expression means something slightly different depending on the target — are the primary blockers to that guarantee.

This draft has been checked against EXTENDING-SEMANTIC-PARITY-table.md to ensure it addresses known issues.

## Architecture Decisions

### 1\. `Arr.*` Mutation Semantics

**DECIDED: by value.** PHP native already gives it for free (copy-on-write). JS, Go and Rust need a wrapper — each for a different reason (JS: references by default; Go: slice aliasing; Rust: ownership/move semantics).

### 2\. `Map.*` Iteration Order and Key Typing

**PROPOSAL, unconfirmed.** Insertion order always guaranteed (impossible with a native Go/Rust `map` — needs its own structure) + keys without coercion (PHP converts `"1"` to `1` in native arrays). Not about losing `null` (PHP already saves it well, `Map.has` already distinguishes it) — the wrapper is needed only for iteration order and key coercion.

### 3\. Fixed Bit Width for `Bit.*`

**DECIDED: 32 bits default.** Mixed widths in one operation: zero-extend to the largest width, treating bits always as unsigned magnitude (consistent with `Bit.shiftR` documented as always-unsigned). Opt-in mechanism to other widths via variable prefix: exact mechanism not closed.

### 4\. Width of `$q`

**DECIDED: 64 bits, using `BigInt` in JS.** Real floor among the eight targets: 64-bit native in all except JS, where a plain `Number` is only exact up to 53 bits. `$q` exists to guarantee exactness, so the option that can silently lose precision is discarded.

### 5\. Compilation Axes: FAST / SAFE / SILENT / DEBUG

**DECIDED — architecture that handles edge cases cross-functionally, without per-function rules.**

-   **SAFE** — checks/casts on every operation, maintains Deterministic Parity even at the edge, at the cost of Performance (matches Portability > Performance in the Design Pillars).
-   **FAST** — no extra checks, the edge may diverge between targets, prioritizes Performance.
-   **SILENT** — the error becomes an inert value (e.g., `0`) and the program continues — the "don't crash the Ariane" mode.
-   **DEBUG** — development environment, with rich error object in the `JSOL.ok` channel for tooling.

### 6\. JSOL-C as a Restricted Profile

**DECIDED.** JSOL-C doesn't need to achieve full parity with the rest of the targets — it's a smaller profile, deliberately. That a function doesn't compile to C (full Unicode case-mapping, `Regex.*`, `JSON.*`) is a documented profile limitation, not an engineering emergency, as long as it's not needed for the subset that JSOL-C does need to cover.
